::W03-R1-Q1 Left-to-Right Associativity::
In Lab 2.10's list of expressions to evaluate, what is the value of <code>8 - 4 - 2</code>?{
=2 #Correct. Operators of the same precedence, like two subtractions, evaluate left to right\: <code>(8 - 4) - 2</code> is <code>4 - 2</code>, which is 2.
~6 #This computes <code>8 - (4 - 2)</code> instead — grouping from the right — but Python evaluates same-precedence operators left to right, not right to left.
~10 #This adds the second value instead of subtracting it.
~-8 #This doesn't match evaluating the expression in order from left to right — double-check the order the subtractions actually happen in.
}

=A float (2.0) — floor division still returns a float whenever either operand is a float, even though the value is rounded down to a whole number #Correct. // rounds down, but it doesn't change the underlying type — mixing in a float keeps the result a float, the same "promotion" rule as with other operators.

::W03-R1-Q3 Why abs() Is Needed::
In the Einstein's Number Puzzle lab, <code>difference</code> is computed as <code>abs(number - rev_number)</code> rather than just <code>number - rev_number</code>. Why is <code>abs()</code> needed here?{
=Because number - rev_number could come out negative depending on which one is larger, and abs() guarantees a positive result either way #Correct. The puzzle needs the positive difference regardless of which of the two numbers happens to be bigger, and abs() removes any negative sign.
~abs() rounds the result to the nearest whole number #abs() only removes a negative sign — it doesn't round or otherwise change a value's precision.
~abs() is required any time you subtract two variables in Python #Subtraction works fine on its own and can validly produce a negative result — abs() is only needed here because the puzzle specifically wants a positive difference.
~abs() converts the result from a float to an int #abs() preserves the type of its argument — an int stays an int, and a float stays a float; it only affects the sign.
}

::W03-R1-Q5 int() vs. round()::
In the POGIL Integers and Floats activity, given <code>euler = 2.7182</code>, what is the key difference between <code>int(euler)</code> and <code>round(euler)</code>?{
=<code>int(euler)</code> truncates to 2 by simply dropping the decimal part, while <code>round(euler)</code> gives 3 by rounding to the nearest whole number #Correct. Truncation always rounds toward zero regardless of the dropped digits, while round() considers the value to find the nearest whole number.
~They both truncate the decimal part and always return the same value #They give different results here specifically because 2.7182 is closer to 3 than to 2 — round() accounts for that, but int() doesn't.

::W03-R1-Q6 String Repetition vs. Numeric Multiplication::
In the POGIL Integers and Floats activity, <code>word = str(pi)</code> turns 3.1415 into the string <code>'3.1415'</code>, and <code>number = float(word)</code> turns it back into the float 3.1415. What's the difference between <code>print(word * 2)</code> and <code>print(number * 2)</code>?{
=<code>word * 2</code> repeats the string's characters, printing <code>3.14153.1415</code>, while <code>number * 2</code> multiplies the value, printing <code>6.283</code> #Correct. The <code>*</code> operator means something different for each type — repetition for a string, multiplication for a number.
~They both print the same numeric result, 6.283, since word and number represent the same value #word is a string, not a number, even though it displays the same digits — <code>*</code> on a string repeats it rather than doing arithmetic.
~word * 2 raises a TypeError, since strings can't be multiplied by a number #Multiplying a string by an int is valid Python and produces repetition — it doesn't raise an error.
~number * 2 repeats the digits of number, just like the string version does #number is a float, and <code>*</code> on a float always means numeric multiplication, never repetition.
}
